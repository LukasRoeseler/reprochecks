Findings (for the authors)

P2 — medium

ADV-001 — The shipped reproducibility data does not regenerate Table 2 exactly (Monte-Carlo drift). Running the author's own committed sim_miller1988.RData through the notebook formula reproduces the printed 120-cell integer table in only 73/120 cells (118/120 within ±2 ms, max deviation 3 ms; e.g. the sk=92 row regenerates as 41,27,19,15,9,7,6,4,3,1 vs printed 41,26,19,18,8,8,6,4,3,1). A fresh R (seed 21) and an independent Python run match the printed table at the same level (64/120 and 68/120 exact; both 117/120 within ±2). Because Table 2 is a Monte-Carlo integer table with a sampling error of ≈1–3 ms, all three agree with the paper's qualitative structure exactly, but the printed run's random stream is not pinned to the shipped data, so exact reproduction is impossible. Impact: provably substantiated that this is a secondary, illustrative simulation; no primary result or conclusion is affected (median bias ↑ with skewness, ↓ with n is reproduced identically in all three). Fix: regenerate Table 2 from the committed sim_miller1988.RData and update the printed integers, and/or report the seed + RNGkind + R version that generated the printed table, and/or report bias with Monte-Carlo SE.

P3 — low

ADV-002 — Figure 1/4/5 bootstrap illustration decimals are not byte-reproducible across R versions. The single-sample bootstrap illustration (sample [355.0,…,1193.2], median 535.6; bootstrap mean 722.6, bias 187, BC 348.6) and the 100/1000-experiment averages (515.1/498.8; 522.1/508.6) depend on R's sample() over the simulated population; the default sample.kind changed (Rounding→Rejection) at R 3.6.0, so R 4.6.1 draws different resamples. The qualitative message (median overestimates the population; BC overshoots on one sample but is near-exact in the long run) is fully reproduced. Fix: pin RNGkind(sample.kind=…) and the R version, or report the illustration values as representative rather than exact decimals.

ADV-003 — One FLP decile trimmed-mean is 1 ms high. Of the nine printed 20%-trimmed-mean decile values (59 66 72 77 82 86 89 91 89), the 5th recomputed to 81 ms vs 82 ms; the other eight match exactly. A small trimming/quantile-estimator convention difference; conclusions unaffected. Fix: clarify/deduplicate the trimming and decile estimator in the notebook.

ADV-004 — Reproducibility package is split across OSF and figshare; the paper's OSF DOI alone does not host it. OSF project 3UZAM (cited in the paper header) contains only a cover-letter PDF and wiki images. The complete package lives on figshare (10.6084/m9.figshare.6911924), which this audit downloaded and used to reproduce the results — so the "Open materials" badge is real and substantiated, but a reader following only the OSF DOI would not find the materials. This rectifies the prior audit's ADV-001/ADV-002, which asserted the figshare package was "not machine-verifiable" — it demonstrably is. Fix: surface the figshare DOI/landing URL prominently in the OSF description and paper; consider mirroring the package on OSF.

ADV-005 — flp_sim_precision.Rmd as shipped would not run (undefined variable). The notebook references bootsamples but assigns all.bootsamples (~lines 90–112), so evaluating it would raise "object bootsamples not found". The committed sim_precision.RData nonetheless reproduces the paper's precision numbers exactly (59/56, 37/38), so the analysis is preserved. Fix: one-line rename.

Rectification of the prior audit

The prior (older-model) audit reported 1 P2 + 2 P3: (a) "code/data not on OSF", (b) "figshare/GitHub links not machine-verifiable", (c) "no random seed reported". This re-audit: (a) is rescoped to ADV-004 (materials are split but present and verified); (b) is refuted — the figshare package is live, complete and was used to reproduce results; (c) is corrected — the code does report set.seed() (4, 21, 44, 7, 666), but a seed alone is insufficient (see ADV-001: even the shipped data doesn't byte-regenerate Table 2).

What this audit does not guarantee

  • No full end-to-end execution of the 16 RMarkdown notebooks. The heavy §4 g&h false-positive/power simulations and the FLP ex-Gaussian fitted true/false-positive simulations (and their 10000×multi-condition loops) were not re-derived from scratch; their qualitative direction was confirmed from the committed sim_gp_*.RData and the one headline FP value (>50%) was verified (max 60.6%). Specific figure-only power-curve ordinates were not re-tabulated.
  • Exact byte-reproduction of Table 2 and the bootstrap illustrations is not achievable from the shipped package on R 4.6.1 (RNG sample.kind drift; exact generating stream unarchived). Agreement is within Monte-Carlo error and is characterized numerically rather than dismissed.
  • Citation counts (Miller 187; Whelan 438; Ratcliff 1930; "as of" 2019 dates) are live Google-Scholar counts at publication time and were not re-derivable.
  • rogme on GitHub (cited for the hierarchical shift function) was referenced but not independently installed/run; the shift-function method itself was verified on the FLP data (deciles) and the qualitative results stand.
  • No pixel-level figure diffing was performed; the shipped PDF figures were treated as reference outputs consistent with their source notebooks, and the load-bearing numbers were recomputed numerically instead.
