This is a substantively reproducible methods paper. The statistical core verifies cleanly: every theorem (1–5) and the appendix's deterministic numerical example reproduce to printed precision (seed 9999), Figure 2 (Beta(13,6)·0.95+0.05, 0.700/0.714) is exact, and Study 1's Table 1 reduces to the paper's values within Monte-Carlo error for all four methods — z-curve over k = 50/100/250, and p-curve 2.1 / ML / p-uniform over k = 100/250, at true power .05–.75 (all deltas ≤ 0.003; the four methods cross-validated in R and p-curve/p-uniform/ML independently in Python). The headline recommendation (z-curve, and the result that fixed-effect-size methods systematically overestimate mean power under effect-size heterogeneity) is supported. The one substantive defect is a code issue, not a results issue: the author's recovered heteroNpunifF contains a lower-tail/upper-tail error (uses pf(datta, log.p=T) for the numerator of the modified p-value) that makes it return a degenerate ≈0.84–0.91 estimate for every true power, contradicting its own published Table 1 p-uniform column; the corrected implementation reproduces the table exactly (ADV-001, P1). Availability is weak: the published code URL osf.io/bvraz resolves to no OSF node (404) and the OSF project holds manuscript files only (ADV-002/003, P2). Minor: Figure 1's "after selection 0.635" label is arithmetically impossible (correct 0.668; ADV-004, P3) and simulation seeds are unreported (ADV-005, P3).

Findings (for the authors)

P1 — high

ADV-001 — The recovered/shipped p-uniform function heteroNpunifF has a tail-direction bug and does not reproduce its own published Table 1 column. In heteroNpunifF (and heteroNpunifCHI) the modified p-value's numerator uses pf(datta, log.p=T) — the log lower tail — instead of pf(datta, lower.tail=F, log.p=T) — the log upper tail (the correct conditional probability P(T>t | T>c)). Run as-is on Study-1-style significant-F data it returns a degenerate ≈0.80–0.91 estimate regardless of true power (true .25 → 0.844; true .05 → 0.808). This reproduces identically at the representative df2=84 and at true per-study df2, isolating the tail error as the cause. The paper's Table 1 p-uniform numbers are correct: the corrected implementation returns .251/.496/.746/.058 exactly matching. Why it matters: the paper carries the badge "verified the analysis reproduced the results", yet one of the four headline estimators' code, run as documented, contradicts its own published column. Fix: change the numerator term to pf(..., lower.tail=FALSE, log.p=TRUE) in heteroNpunifF/heteroNpunifCHI, re-verify Study 1, and host the corrected file.

P2 — medium

ADV-002 — The published code-availability URL https://osf.io/bvraz does not resolve to an existing OSF node. OSF API /v2/nodes/bvraz/ → HTTP 404 (node does not exist; the web 200 is OSF's generic fallback for unknown short-links). The draft LaTeX instead cites http://www.utstat.toronto.edu/~brunner/zcurve2018, also dead (recoverable only via the Wayback Machine, 9 captures 2018–2026; the estimator file estimatR.txt was recovered from the 2022-05-19 capture). Fix: create the bvraz component (or correct the statement) and host estimatR.txt + the simulation drivers; update the draft-URL references.

ADV-003 — OSF project PEUMW contains manuscript files only; the "Open Materials"/"analysis reproduced" badges are weakly substantiated. The project holds six folders (Submission, two Review Rounds, three Revisions) with LaTeX/PDF and editorial PDFs but no R source, no simulation data, no analysis scripts. The "All supplementary files can be accessed at OSF" statement is only partially true, and the only documented code path (bvraz) is dead. Fix: upload estimatR.txt and the full replication drivers to the project.

P3 — low

ADV-004 — Figure 1's "after selection 0.635" caption is arithmetically inconsistent with Uniform[0.05,1]. E[p|sig] = E[p²]/E[p] = ((1³−.05³)/3)/((1²−.05²)/2) = 0.6683, not 0.635; no interval [a,b] yields before 0.525 and after 0.635 simultaneously. R and Python agree on 0.6683. Illustrative only; affects no simulation result. Fix: correct the label to 0.668 (or recompute for the shown distribution).

ADV-005 — Random seeds for the 10,000-sim coexistence runs are not reported. Exact replication of the specific published point estimates is impossible; reduced-MC fixed-seed re-runs reproduce all Table 1 means within ~0.003, so practical impact is low. Fix: state the seed(s) in the supplement.

Cross-check vs. the prior audit (two independent audits)

Convergent (factual): OSF project PEUMW holds manuscript files only (no code/data); the draft's utstat code URL is dead (archive-only); Figure 1's "0.635 after selection" is arithmetically impossible (both audits compute 0.6683); z-curve/p-curve reproduce Table 1 within MC error. Divergent (method), resolved: the prior audit marked the p-uniform and ML Table-1 columns "➖ not verified" (its fixed-df2 application of the author functions gave ~0.85). This re-audit deeper-reimplements: with true per-study df2, ML and p-curve reproduce exactly, and the p-uniform ~0.85 artifact is traced to the author function's lower-tail bug — resolved in favor of the values that match the paper's own reported numbers (corrected upper-tail reproduces Table 1 exactly). The prior audit keyed availability to the dead utstat draft URL; this audit additionally confirms the published code URL (osf.io/bvraz) is a dead 404 node — a stronger provenance finding. Shared gap: neither audit re-ran the unrecovered 10,000-sim driver or Studies 2–3; those remain the natural next step.

What this audit does not guarantee

  • Studies 2 and 3 were not reimplemented (gamma-es ML and correlated n–es designs; computational infeasibility + unrecovered simulation drivers). Their Tables 3–5 are ➖, not verified here.
  • The OSC-100 application (66%/37%/97%) and the Irvine-Hall / bandwidth-0.05 numbers are not independently recomputed (external data/method not shipped) — ➖.
  • The reduced Monte Carlo uses S ≈ 500–2000 (not the paper's 10,000) per cell; agreement is established to the reduced-MC tolerance (≈0.003 at k=100–250), not to the paper's own 10,000-sim precision.
  • The exact simulation drivers that produced Tables 1, 3, 5 were not recovered; Study-1 agreement was obtained by reimplementing the described design with the author's estimator functions (not a byte-for-byte rerun of the unrecovered driver).
  • The True-power .05 cell hit an optimizer boundary in the Python lane only (R is correct); a scipy bounded-optimizer fragility, not a manuscript error.
  • No live re-run of the authors' original driver was possible (code not on OSF; only archived estimator functions recovered).
